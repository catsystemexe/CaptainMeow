# U1.3 — Basic Setup as part of all Enemy Lab presets

## Goal

Establish a shared Enemy Lab Basic Setup model and bind the active FSM preset draft to the visible Basic Setup controls while preserving the existing runtime spawn contracts. U1.3 also defines the Simple and Smart preset envelope shape at the Dev UI/model boundary without rewriting their behavior editors.

## Product model

Enemy Lab presets are modeled as:

```text
Preset = Basic Setup + mode-specific behavior
```

At the Dev UI/model boundary each preset has `mode`, `basicSetup`, and `behavior`. Runtime content registries remain stable; the unified envelope is an Enemy Lab authoring/draft model rather than a forced runtime schema migration.

## Starting preset architecture

- Simple and Smart used immutable movement behavior preset IDs from `EnemyBehaviorPresets`; their visible setup came from shared spawn controls, not persisted lab presets.
- FSM used `FsmPresetEditorModel` for ID/label/source selection and `FsmPresetAuthoringModel` for graph behavior editing.
- FSM user persistence lived in `UserFsmPresetStore` under storage envelope version `1`.
- FSM Basic Setup from U1.2 was UI/spawn-control state only and was not saved into presets.
- The top FSM compact preset dropdown and lower editor selection both existed; U1.3 keeps them synchronized by routing top dropdown changes through `FsmPresetEditorModel.select()`.

|---|---|---|---|---|
| Simple | `BehaviorPreset` movement descriptor | `EnemyBehaviorPresets` / content JSON | shared spawn controls | shared `EnemyLabPresetEnvelope` shape documented and smoke-tested; runtime movement registry unchanged |

## Shared Basic Setup schema

Implemented in `src/dev/EnemyLabPresetModel.ts`:

```ts
type EnemyLabBasicSetup = {
  appearanceId: string;
  count: number;
  formationId?: FormationId;
  spacing?: number;
  elasticity?: number;
  baseSpeed: number;
  spawnY: number;
};
```

The shared helpers are:

- `defaultBasicSetupForMode(mode)`
- `normalizeBasicSetup(input, mode)`
- `cloneBasicSetup(setup)`
- `validateBasicSetup(setup)`
- `withNormalizedBasicSetup(preset, mode)`

## Field ownership classification

| Field | Classification | Runtime payload | Default/range | U1.3 persistence |
|---|---|---|---|---|
| `appearanceId` | preset-owned | `typeId` / `enemyTypeId` | default `red`; must exist in `ENEMY_DEFS` | persisted in FSM user presets and envelope model |
| `count` | preset-owned with spawn effect | single vs group dispatch | integer `1..10`, default `1` | persisted in FSM user presets and envelope model |
| `formationId` | preset-owned group setup | `formationId` | runtime formation IDs, default `line.horizontal` | persisted in FSM user presets and envelope model |
| `spacing` | preset-owned group setup | `params.formation.spacing`; radial formations also map to `radius` | `16..96`, step `2`, default `18` | persisted in FSM user presets and envelope model |
| `elasticity` | preset-owned adapter over current group cohesion | maps to `cohesionId`, `response`, `maxCatchupSpeed` | integer `0..10`, default `0` | persisted in FSM user presets and envelope model |
| `baseSpeed` | preset-owned data, runtime integration deferred | none in U1.3 | `0..720`, step `5`, defaults: simple/fsm `115`, smart `90` | persisted/displayed; no hidden runtime multiplier |
| `spawnY` | preset-owned spawn setup | `spawn.y` / group `anchor.y` after current FSM UI-to-runtime mapping | `0..504`, default `260` | persisted in FSM user presets and envelope model |

## Defaults and normalization

Legacy or built-in presets missing `basicSetup` normalize into deterministic mode defaults when loaded into a draft. This does not mutate storage during read. Normalized values are written only when the user saves a user preset.

## Validation

`validateBasicSetup()` checks appearance existence, count range, formation validity for groups, spacing range, elasticity range, finite/ranged `baseSpeed`, and logical `spawnY` bounds. The FSM editor model blocks save when Basic Setup validation has errors.

## Simple preset integration

Simple keeps existing runtime movement preset resolution. U1.3 introduces and smoke-tests the Dev UI envelope shape for Simple as `mode: "simple"`, `basicSetup`, and `{ behaviorPresetId }` behavior data. Full Simple behavior editor redesign and hosted user store UI remain deferred.

## Smart preset integration

Smart keeps existing runtime movement preset resolution. U1.3 introduces and smoke-tests the Dev UI envelope shape for Smart as `mode: "smart"`, `basicSetup`, and `{ behaviorPresetId }` behavior data. Full Smart behavior editor redesign and hosted user store UI remain deferred.

## FSM preset integration

FSM user presets now persist `basicSetup` on `FsmPresetSchemaV1`. `FsmPresetEditorModel` loads normalized Basic Setup for built-ins, users, and legacy users. `save()` writes ID, label, and Basic Setup into the user preset while preserving the graph behavior.

## Selection synchronization

Changing the top FSM compact preset dropdown selects the same ID in `FsmPresetEditorModel`, reloads `FsmPresetAuthoringModel`, refreshes the Basic Setup controls, refreshes state selection, and updates Preview Saved availability.

## Draft ownership

FSM has one active selected ID and one preset draft in `FsmPresetEditorModel`; graph behavior remains owned by `FsmPresetAuthoringModel`. Basic Setup controls bind to `presetModel.draft.basicSetup`.

## Dirty tracking

Changing FSM Basic Setup fields updates `draft.basicSetup` and marks the preset draft dirty. Built-in drafts can become locally dirty for preview/spawn iteration but cannot be saved directly; the edit action duplicates built-ins to user presets.

## Save behavior

Saving a user FSM preset validates Basic Setup, preserves graph behavior, writes `basicSetup`, refreshes the user registry, keeps the selected user preset, and clears dirty state.

## Built-in immutability

Built-ins are not written to storage. Save on a dirty built-in draft fails with `E_BUILTIN_READONLY`; the top `✎` action duplicates a built-in into a user preset before editing.

## User persistence

FSM persistence remains storage envelope version `1` at key `captain-meow.fsm.user-presets.v1`. User preset JSON now includes optional `basicSetup` beside `schemaVersion`, `metadata`, and `graph`.

## Legacy compatibility

Old FSM user presets without `basicSetup` continue to load. The editor draft receives normalized defaults, storage is not mutated during read, and the defaults become persisted only after the user saves.

## Base Speed status

`baseSpeed` is displayed in FSM Basic Setup as `Speed`, persisted in the preset draft, exported/imported with FSM user presets, validated, and covered by smoke tests. U1.3 does not change runtime movement math or add per-state speed multipliers. Existing behavior/FSM movement preset speeds remain authoritative at runtime to avoid double-applying speed. Runtime multiplier integration is deferred.

## Import / Export

FSM import/export includes `basicSetup` automatically because it is part of `FsmPresetSchemaV1` and validation preserves unknown-compatible object fields. The new smoke verifies exported and imported FSM presets preserve `basicSetup.baseSpeed` and graph behavior. Simple/Smart import/export UI remains deferred with the shared envelope foundation in place.

## Preview Draft behavior

Preview Draft still uses the current FSM graph draft through `FsmPreviewSession`. Basic Setup is saved as preset setup data; U1.3 does not move preview spawn coordinates to Basic Setup.

## Preview Saved behavior

Preview Saved still resolves the selected persisted preset ID through `CONTENT.fsmPresets`. If the selected user preset has saved `basicSetup`, that data is available on the persisted definition; preview runtime FSM graph behavior remains unchanged.

## Normal Spawn policy

Normal FSM Spawn follows the current visible draft Basic Setup controls for Type/Count/Form/Spacing/Elasticity/Y and the current selected preset ID for `fsmPresetId`. This preserves the U1.2 fast-iteration policy and avoids silently changing runtime spawn semantics.

- Preview coordinate/appearance behavior still uses existing preview session contracts; any future Preview/Diagnostics redesign should explicitly consume Basic Setup if desired.
