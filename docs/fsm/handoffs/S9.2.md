# S9.2 — Prove and restore actual Enemy Lab runtime mounting

## Why S9.1 was incomplete

S9.1 proved source-level mount/style properties only. It did not execute `DevSummoner.init()` in a DOM-like runtime and therefore missed an initialization exception that occurs before `document.body.appendChild(panel)`.

## Proven runtime root cause

`DevSummoner.init()` calls `renderPresetEditor()` before appending the root panel. The S9 preset editor attempted to assign directly to `fsmSpawnSelect.value`, but `createCompactSelect()` exposes `value` as a getter-only property. Because browser modules run in strict mode, that assignment throws `TypeError: Cannot set property value ... which has only a getter` during initialization. `src/main.ts` caught the exception and logged a warning, but the panel had not yet been appended, so Enemy Lab was absent at runtime.

## Actual boot/mount path

The Replit/browser path is:

```text
index.html
→ /src/index.ts
→ import "./main"
→ main()
→ createGame(...)
→ mountEnemyLabRuntime(game, LOGIC_W, LOGIC_H)
→ new DevSummoner(...)
→ DevSummoner.init()
→ create root panel and S9 preset editor
→ document.body.appendChild(panel)
```

`DevSummoner` is instantiated through `mountEnemyLabRuntime()`, mount/init is invoked after `createGame()` and after `document.body` exists, and the result is retained at `window.__CM.enemyLab` for runtime diagnostics.

## Exact fix

- Fixed the getter-only assignment by passing the selected preset id back through `refreshFsmSpawnSelect(...)`, which uses `setOptions(..., preferred)` and preserves the compact-select contract.
- Added `mountEnemyLabRuntime()` as the actual runtime bootstrap used by `src/main.ts`.
- The bootstrap prevents duplicate panel creation, validates `document.body`, returns mount diagnostics, and exposes connected root/preset elements through the retained runtime result.

## Runtime DOM/geometry evidence

`src/dev/EnemyLabRuntimeMount.smoke.ts` executes the real bootstrap function with a DOM-capable fake document and proves:

- `DevSummoner` construction occurs.
- `init()`/mount is invoked without exception.
- `dev-summoner` is appended exactly once.
- `dev-summoner` and `ds-fsm-preset-editor` are connected.
- root style is not `display:none` or `visibility:hidden`.
- root has explicit non-zero width and viewport-bounded height.
- fake runtime geometry is non-zero and intersects the viewport contract.
- a visible `Enemy Lab` title and `FSM Presets` section exist.
- repeated bootstrap calls reuse the existing panel.
- S10 graph/state authoring controls remain absent.
