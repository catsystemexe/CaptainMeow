# S6 — Lifecycle entry actions and explicit despawn

## Session commit

The commit containing the S6 implementation.

## Goal

Activate FSM state-entry lifecycle execution for the MVP action set and route explicit `despawn` through the standard mark-kill plus Cleanup lifecycle without adding scripting, spawn/summon, VFX/audio, persistence, UI, or canonical content conversion.

## Starting S5 lifecycle state

- `enterActions` already existed in schema/resolved state data as `lifecycle.enterActions` with MVP descriptor support for `{ type: "despawn" }`.
- Formal entry already flowed through `enterResolvedFsmState` for spawn, transitions, and self-transitions.
- `EntityStore.markKill(ref)` was the standard idempotent kill marker and `CleanupSystem` delegated removal to `store.cleanup()`.
- S2 migration already mapped a legacy terminal state named exactly `despawn` with no outgoing transitions to `lifecycle.enterActions = [{ type: "despawn" }]`, but S5 still left that data unexecuted.

## Implemented scope

- Added a narrow lifecycle executor for formal state entry.
- Executed state `enterActions` exactly once per formal entry.
- Supported only the existing `{ type: "despawn" }` action.
- Threaded a mark-kill lifecycle context through SpawnSystem initial entry and EnemySystem transition/self-transition updates.
- Added same-tick early-out after despawn so movement, targeting-derived movement, combat, position integration, culling, and state-age increment are skipped for that entity on the despawn tick.
- Added focused lifecycle/despawn smoke coverage and registered the new smokes before the known BombExplosionChain runner failure.
- Extended validation diagnostics for duplicate despawn actions and immediate cycles containing side-effecting entry actions.

## Lifecycle execution contract

- Spawn entry: `SpawnSystem` creates the entity first, then creates the FSM runtime snapshot with a lifecycle context that calls `store.markKill(spawnedRef)`.
- Transition entry: `updateResolvedFsm` calls `enterResolvedFsmState` once for the first matching transition and executes the target state's entry actions from that single entry path.
- Self-transition: self-transition remains a full formal entry and re-runs the target state's entry actions once.
- Exactly-once behavior: actions execute only inside `enterResolvedFsmState`, after state index, age, movement runtime, combat selection, entry count, and internal reset/cleanup are applied.
- No-transition behavior: no ordinary tick replays entry actions.

## Despawn semantics

- `despawn` calls the injected lifecycle context's `markKill`, which is wired to `EntityStore.markKill(ref)` in system integration.
- `EntityStore.markKill` sets `pendingKill` and is idempotent; it does not remove the entity.
- If a despawn action kills the entity on entry, `updateResolvedFsm` reports `entityKilled: true` and does not increment state age.
- `EnemySystem` returns immediately when the FSM step reports `entityKilled`, skipping individual movement, group cohesion, behavior fallback, position integration, attack controller, and culling for that entity in the same tick.
- `CleanupSystem`/`EntityStore.cleanup()` remains the only removal owner. A spawn-entry despawned entity can exist as pending-kill until Cleanup; depending on frame scheduling it may be observable to render/debug readers before Cleanup, but S6 does not change render phase ordering.

## Idempotency

- The lifecycle executor checks `pendingKill`/`isKilled` before calling `markKill`, so duplicate despawn actions and already-killed entities do not produce duplicate mark calls.
- Duplicate actions are still counted as executed actions for diagnostics and ordered execution observability.
- Repeated update calls before Cleanup do not replay entry actions unless another formal entry occurs; EnemySystem skips entities already marked `pendingKill` at the top of its iteration.

## Validation changes

- Existing terminal-state warning for outgoing transitions after despawn is retained as `W_TERMINAL_STATE_TRANSITIONS`.
- Immediate cycles still produce `E_IMMEDIATE_CYCLE`.
- Immediate cycles whose cycle nodes contain entry actions also produce hard error `E_IMMEDIATE_ACTION_CYCLE`.
- Duplicate despawn actions produce warning `W_DUPLICATE_DESPAWN_ACTION`.
- Initial despawn remains allowed.

## Built-in migration activation

- S2's migrated legacy `despawn` lifecycle data is now active when the state is entered.
- Runtime semantics are explicit-data based: a state named `despawn` without an enter action does not kill, and a differently named state with `{ type: "despawn" }` does kill.
- Canonical `behaviorGraphs.json` remains legacy JSON for S7; S6 does not convert built-in content.
