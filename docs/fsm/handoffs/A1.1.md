# A1.1 — Live FSM runtime diagnostics

## Goal

Add live, read-only diagnostics to FSM mode so browser runs can compare the authoritative single-enemy FSM runtime with the authoritative group-anchor FSM runtime and one non-authoritative group member.

## Why diagnostics were required

A read-only A1 audit found that group FSM preset IDs resolve, group anchor runtimes exist, anchor FSM movement is evaluated, and normal group movement is suppressed. The remaining browser discrepancy needed live evidence for preset identity, state transitions, scrollX/screenX, anchor movement, member suppression, and stale bundle detection.

## Runtime snapshot model

`src/dev/FsmRuntimeDiagnostics.ts` defines `FsmRuntimeDiagnosticSnapshot` with kind, authoritative flag, preset/state/movement IDs, world/screen position, scrollX, velocity, state age, last transition, movement suppression, and optional member count.

## Single runtime source

Single diagnostics read the actual enemy entity FSM runtime via `getFsmDebugSnapshot()` and the entity `pos`/`vel` fields used by `EnemySystem`.

## Group anchor runtime source

Group diagnostics read the authoritative `EnemyGroupRegistry` group record, including the stored anchor FSM runtime, anchor position, anchor velocity, member count, and the recorded group FSM transition scrollX context.

## Group member runtime source

The representative member is the most recent live member associated with the Enemy Lab diagnostic spawn token. It is shown only as non-authoritative movement because group cohesion owns movement while the group exists.

## Authoritative versus non-authoritative state

The UI labels single diagnostics as `SINGLE — AUTHORITATIVE`, group anchor diagnostics as `GROUP ANCHOR — AUTHORITATIVE`, and representative member diagnostics as `MEMBER — NON-AUTHORITATIVE MOVEMENT`.

## scrollX and screenX reporting

Single diagnostics use the world `scrollX` observed by DevSummoner. Group anchor diagnostics show the actual transition-evaluation scrollX currently passed to the anchor FSM; A1.1 records and displays `0` for the existing hard-coded group-anchor context. Screen X is always reported as `worldX - scrollX`.

## Last transition reporting

`FsmRuntimeSnapshot` now carries optional diagnostic-only `lastTransition` metadata (`from`, `to`, `reason`, `atStateAge`) when `updateResolvedFsm()` takes a transition. This does not change transition selection, timing, movement, preset data, serialization, or saved content.

## Runtime selection/correlation

DevSummoner sends its dev-only `devManualSpawnId` with FSM group spawns, matching existing single-spawn diagnostic correlation. `SpawnSystem` copies that dev-only token to group members. The diagnostics provider follows the newest live FSM entity with the latest token and, for grouped members, resolves the authoritative group anchor through `window.__CM.enemyGroups`.

## UI placement

The compact `RUNTIME DIAGNOSTICS` block is inserted in FSM mode after `BASIC SETUP` and before the FSM behavior/editor panel.

## Refresh lifecycle

Diagnostics refresh through the existing DevSummoner 250 ms refresh timer, stop when DevSummoner is destroyed with the existing cleanup, and render `No FSM runtime spawned` when the tracked runtime no longer exists.

## Diagnostic version marker

The UI displays `Diagnostics version: A1.1` to help identify stale browser bundles.

## Manual browser checklist

1. Open FSM mode.
2. Confirm `RUNTIME DIAGNOSTICS` and `Diagnostics version: A1.1`.
3. Select FSM Charge.
4. Count = 1, Spawn.
5. Record preset, state, movement, world X, scrollX, screen X, velocity, and transition.
6. Count = 2, Spawn.
7. Record the same values for `GROUP ANCHOR — AUTHORITATIVE`.
8. Confirm the member is marked `MEMBER — NON-AUTHORITATIVE MOVEMENT` and suppressed.
9. Observe whether the group enters charge and when.
10. Repeat for Hover and confirm the transition into `hover` / `none.hold` is visible.
11. Repeat for Turret.
12. Compare single versus group scrollX.
13. Confirm diagnostic version proves the current bundle.
14. Capture screenshots or copied diagnostic text for the user report.

Manual browser verification was not performed in this non-interactive environment.
