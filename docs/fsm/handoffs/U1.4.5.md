# U1.4.5 — Group draft behavior fix and Enemy Lab layout refinement

## Confirmed browser findings
The task reported that Count = 1 draft behavior edits worked, Count > 1 worked without state Behavior edits, and Count > 1 failed after an unsaved state Behavior edit. Manual browser verification was not performed in this environment.

## Runtime regression matrix
- Count = 1 with an unsaved draft state Behavior edit now resolves the draft override into the spawned enemy runtime.
- Count = 2 with the same unsaved draft state Behavior edit now resolves the same draft override into the group anchor runtime.
- Count = 5 with the same unsaved draft state Behavior edit now resolves the same draft override into the group anchor runtime.

## Runtime root cause
`createDevSummonerGroupSpawnPayload` accepted `resolvedFsmPresetOverride` but did not copy it into the returned `SPAWN_ENEMY_GROUP` payload. The single-enemy helper did copy the override into `SPAWN_ENEMY`, so Count = 1 used the edited draft graph while Count > 1 forced `SpawnSystem` to re-resolve by `fsmPresetId` from saved content and lost unsaved state Behavior edits.

## Single draft behavior path
Current FSM draft → `resolveEphemeralFsmPreset` → `resolvedFsmPresetOverride` → `SPAWN_ENEMY` → `SpawnSystem` → entity FSM runtime → edited movement preset.

## Group draft behavior path
Current FSM draft → `resolveEphemeralFsmPreset` → `resolvedFsmPresetOverride` → `SPAWN_ENEMY_GROUP` → `SpawnSystem` → `EnemyGroupRegistry` → group anchor FSM runtime → edited movement preset.

## Production fix
The group spawn payload helper now preserves `resolvedFsmPresetOverride` on the returned payload. `SpawnSystem` already preferred the preview override for group anchors and members, so no spawn architecture change was required.

## Runtime proof
`src/game/enemies/FsmDraftBehaviorGroupRuntime.smoke.ts` duplicates a known built-in into an editable user preset, changes the first state Behavior in the draft, and verifies Count = 1, Count = 2, and Count = 5 runtime snapshots use the edited movement preset.

## Saved storage behavior
The runtime smoke verifies saved content remains unchanged after the draft edit, reload without Save restores the saved Behavior, and Save persists the edited Behavior.

## Enemy Lab width
The whole Enemy Lab panel now uses a wider responsive `clamp` width, while the FSM inner section inherits the full panel width instead of imposing a separate cap.

## PRESETS layout
PRESETS renders heading first, icon toolbar second, and the current preset control below the toolbar. The redundant visible Preset label is absent.

## Preset side popover
The compact preset control uses a fixed-position side popover anchored to the current preset button. It opens to the right when possible, flips left when needed, and closes on selection, outside click, or Escape.

## BASIC SETUP type/count row
BASIC SETUP now places Type and the count stepper on one row.

## Diagnostics toggle
The STATES heading includes a Runtime Diagnostics toggle icon with title and aria-label. The toggle state persists while the Enemy Lab instance remains mounted.

## Diagnostics side dock
Runtime Diagnostics now mounts once in the states diagnostics dock and appears beside the state editor when toggled on.

## Responsive fallback
The panel is capped to the viewport on narrow screens, and the diagnostics dock uses compact grid sizing so it can collapse safely with the panel.
