# U1.1 — SIMPLE / SMART / FSM mode split

## Goal

Split Enemy Lab into one top-level controller-mode choice with native `SIMPLE`, `SMART`, and `FSM` buttons, while preserving the existing Single/Group controls, movement spawn contracts, FSM spawn selector behavior, authoring model, Preview workflow, diagnostics, and vertical layout.

## Starting UI structure

Before U1.1, `DevSummoner.init()` mounted a single vertical panel:

```text
Enemy Lab title
└─ Spawn
   ├─ Spawn Mode: Single / Group
   ├─ Single controls (`enemyControls`)
   │  ├─ Type
   │  ├─ Movement Dumb/Smart selector
   │  ├─ Primitive/Preset selector
   │  └─ Y Spawn
   ├─ Group controls (`groupControls`)
   │  ├─ Type + count stepper
   │  ├─ formation/cohesion/facing/parameter controls
   │  ├─ Move Dumb/Smart selector
   │  ├─ Prim/Preset selector
   │  └─ Y Spawn
   ├─ shared FSM selector (`fsmSpawnWrap` / `#ds-fsm-preset`)
   └─ RELEASE / Spawn Group
FSM preset editor and authoring panel
FSM runtime diagnostics panel
```

Single/Group visibility was owned by `refreshModeButtons()`, which mutated `enemyControls.style.display`, `groupControls.style.display`, `aria-pressed`, and the shared spawn button label. The FSM selector had already been moved into the shared spawn section by U0.2 so both Single and Group could read it.

## Implemented mode model

U1.1 adds:

```ts
type EnemyLabMode = "simple" | "smart" | "fsm";
```

`enemyLabMode` is local in `DevSummoner.init()`, defaults to `"simple"`, and is not persisted. Mode switching calls `refreshEnemyLabMode()` and does not recreate the panel, editor models, preview session, compact selects, Single/Group state, or diagnostics state.

## Top navigation

The first interactive row after the Enemy Lab title is `#ds-enemy-lab-mode-row` containing exactly three native buttons:

```text
SIMPLE | SMART | FSM
```

Each button is keyboard-focusable as a native button, sets `aria-pressed`, and receives active/inactive styling through `styleLabModeButton()`. There are no links or page navigation.

## Simple Lab contents

`simpleLabSection` is `#ds-simple-lab-section` and is labelled `SIMPLE LAB`.

When active it owns the single shared `#ds-shared-spawn-section`, with:

- existing Single/Group segmented spawn-mode controls,
- existing Single Type selector,
- existing Single Y Spawn slider/input,
- existing Group Type/count, formation, cohesion, facing, parameter, and Y Spawn controls,
- existing movement primitive/preset compact controls forced to the non-smart (`dumb`) movement class,
- existing RELEASE / Spawn Group action.

The shared FSM selector is hidden outside FSM mode, so Simple does not expose FSM authoring/spawn controls. Simple normal spawn emits `behaviorPresetId` and omits `fsmPresetId`.

## Smart Lab contents

`smartLabSection` is `#ds-smart-lab-section` and is labelled `SMART LAB`.

When active it owns the same single shared `#ds-shared-spawn-section`, with the existing Single/Group controls and movement primitive/preset compact controls forced to the `smart` movement class. Smart normal spawn emits `behaviorPresetId` and omits `fsmPresetId`.

## FSM Lab contents

`fsmLabSection` is `#ds-fsm-lab-section` and is labelled `FSM LAB`.

When active it owns:

- the same shared spawn block,
- the visible shared FSM selector `#ds-fsm-preset`,
- the existing FSM preset editor panel `#ds-fsm-preset-editor`,
- built-in/user preset controls,
- preset details,
- state authoring,
- movement/modifier/targeting/combat/lifecycle fields,
- transitions,
- validation/diagnostics,
- Preview Draft, Preview Saved, Restart, and Stop controls,
- Preview status, diagnostics, and transition trace,
- runtime diagnostics / ended snapshot panel `#ds-enemy-lab-debug`.

The FSM selector remains visible in FSM mode for both Single and Group.

## Shared controls retained

The Single/Group spawn block is intentionally retained as one shared DOM subtree instead of being cloned three times. This avoids duplicating listeners, compact-select document handlers, form state, group stepper state, and spawn event paths.

The shared controls are:

- `#ds-shared-spawn-section`,
- Single/Group buttons,
- `enemyControls`,
- `groupControls`,
- movement compact selects,
- group formation/cohesion/parameter controls,
- Y Spawn controls,
- the RELEASE / Spawn Group button,
- the FSM selector wrapper, visible only in FSM mode.

## DOM ownership and event handlers

`refreshEnemyLabMode()` moves the existing `#ds-shared-spawn-section` into the currently active vertical lab with `appendChild()`. Moving the node preserves all child input values and event listeners.

No second spawn button is created. The original spawn button listener still owns both event paths:

```text
Single → EventType.SPAWN_ENEMY
Group  → EventType.SPAWN_ENEMY_GROUP
```

Mode buttons only update `enemyLabMode` and visibility. They do not emit spawn events and do not start additional refresh timers.

`refreshModeButtons()` still owns Single/Group visibility and button labels inside the shared spawn block.

The FSM preset editor, authoring model, and preview session are constructed once and remain mounted in `fsmLabSection`.

## Visibility rules

`refreshEnemyLabMode()` implements exactly:

```text
simple → #ds-simple-lab-section display:flex; #ds-smart-lab-section/#ds-fsm-lab-section display:none
smart  → #ds-smart-lab-section display:flex; #ds-simple-lab-section/#ds-fsm-lab-section display:none
fsm    → #ds-fsm-lab-section display:flex; #ds-simple-lab-section/#ds-smart-lab-section display:none
```

Hidden labs use `display: none`, occupy no layout space, and have their focusable descendants assigned `tabIndex = -1` by `setLabSectionFocusable()`. The active lab's descendants are restored to `tabIndex = 0`.

The layout remains vertical; no horizontal or three-column lab layout was added.

## State preservation behavior

Mode switching does not destroy or recreate stateful controls. The shared spawn section moves between labs as the same DOM node. The FSM editor model, authoring model, dirty state, preview session, diagnostics panel, and user preset selector remain live.

Movement controls now remember primitive/preset selection per movement class, so switching Simple ↔ Smart restores the previous non-smart/smart values instead of resetting them.

## Spawn contract preservation

- Simple Single spawn emits `behaviorPresetId` from the existing non-smart movement preset and omits `fsmPresetId`.
- Smart Single spawn emits `behaviorPresetId` from the existing smart movement preset and omits `fsmPresetId`.
- FSM Single spawn emits `fsmPresetId` from `#ds-fsm-preset` and omits `behaviorPresetId`.
- FSM Group spawn emits `fsmPresetId` from `#ds-fsm-preset`; group movement remains controlled by the existing group movement preset and SpawnSystem group ownership path.
- FSM IDs are never written into `behaviorPresetId`.
- Draft Preview remains `resolvedFsmPresetOverride`-based through `FsmPreviewSession`; Saved Preview remains registry-backed.

## U0/U0.1/U0.2 compatibility

U1.1 keeps the U0 contract separation:

```text
behaviorPresetId → Simple/Smart movement preset
fsmPresetId → explicit normal FSM controller
resolvedFsmPresetOverride → Draft Preview only
```

U1.1 keeps U0.1 group forwarding behavior by continuing to pass selected `fsmPresetId` in group payloads only in FSM mode.

U1.1 keeps U0.2 group selector visibility by making `#ds-fsm-preset` visible in FSM mode regardless of Single/Group.

User FSM options still come from the live `CONTENT.userFsmPresets.registry()` list, and `refreshEnemyLabMode()` refreshes the FSM selector when entering FSM mode.

## Explicitly deferred to U1.2+

- separate draft models
- Count-based Single/Group
- Type-to-Appearance rename
- removal of parallel group behavior in FSM mode
- FSM-controlled group anchor
- editor model consolidation
- horizontal layout
- visual polish

## Risks and inputs for U1.2

- The shared spawn block is moved between vertical labs rather than cloned. This preserves state and listener safety, but U1.2 should account for that ownership model before introducing Count-based UI or separate draft models.
- Simple and Smart currently reuse the existing movement controls with per-class selection memory. If U1.2 creates fully separate controls, it must preserve `behaviorPresetId` semantics and group movement ownership.
- FSM mode intentionally keeps the existing group movement selectors visible; removing/suppressing them remains deferred.
