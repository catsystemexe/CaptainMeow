# U1.4.12 — Trigger time live UI synchronization

## Confirmed browser symptom
Trigger numeric stepper clicks updated the authoring draft but the inline numeric display stayed stale until another full editor render.

## Root cause
The trigger stepper click handler mutated its closed-over value and committed to the authoring model, but did not write the normalized value back to the stable value DOM node after the live commit.

## Model mutation path
`makeTriggerStepper` click handler → trigger-specific commit callback → `FsmPresetAuthoringModel.setLabTrigger(...)` → authoring draft transition condition params.

## Stale DOM target
The stepper value `<span>` inside the trigger parameter row was only updated by `setValue(...)` during full `renderPresetEditor()` passes.

## Live update implementation
The trigger stepper click handler now writes the formatted post-click value into the value node and refreshes the decrement disabled state immediately after commit.

## Summary synchronization
State row trigger summary nodes are tracked by state id during render, and live-status refresh updates their text from `authoringModel.labStateRows()`.

## Dirty/save/preview synchronization
The existing `updateStateEditorLiveStatus()` path remains the live synchronization point for dirty badge, diagnostics, details, and save button availability.

## Trigger semantics unchanged
No runtime trigger condition, transition, or FSM evaluation semantics were changed.
