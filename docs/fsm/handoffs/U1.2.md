# U1.2 — FSM Presets and Basic Setup workflow

## Goal

Rework only the top of the active FSM Lab so the vertical workflow is `PRESETS`, then `BASIC SETUP`, then the existing FSM editor, Preview, Diagnostics, and Runtime Trace. Runtime spawn semantics are preserved.

## Approved UI structure

```text
FSM
├─ PRESETS
├─ BASIC SETUP
└─ existing FSM editor / Preview / Diagnostics below
```

## Starting FSM top workflow

U1.1 put the shared `Spawn` block inside FSM mode. It still showed the shared `Spawn Mode` Single/Group segmented control, separate Single and Group control panels, a separate visible `FSM` selector row, text-based group formation and cohesion controls, stepper-based spacing/tight/catch controls, and `RELEASE` / `Spawn Group` button text.

## PRESETS implementation

The new top preset block is `#ds-fsm-preset-section` with heading `PRESETS`, one compact preset dropdown `#ds-fsm-preset`, and compact action toolbar `#ds-fsm-preset-toolbar`. The redundant visible row label `Preset` is not used in this top block.

## Icon action mapping

- `+` maps to the existing `presetModel.create()` New preset path.
- `✎` maps to the existing safe edit path: user presets remain editable in the lower editor; built-ins are duplicated via `presetModel.duplicate()` before editing.
- `⇧` maps to the existing import path using the lower import text and collision selector.
- `×` maps to the existing delete path for selected user presets.

Each icon button has `title` and `aria-label`.

## Built-in versus user action rules

Built-ins remain read-only. Delete is disabled for built-ins. The pencil action does not mutate built-ins directly; it duplicates built-ins through the existing model path. User presets remain mutable through the existing lower editor/model controls.

## BASIC SETUP implementation

`#ds-fsm-basic-setup` appears immediately after PRESETS. It contains:

```text
BASIC SETUP
Type
Count
Form
Spacing
Elasticity
Y Spawn
SPAWN
```

The `Type` and `Y Spawn` controls reuse the existing spawn controls so the coordinate and type semantics do not change.

## Count-driven Single/Group behavior

FSM mode no longer uses the separate visible Single/Group selector. `Count` is normalized by `normalizeFsmSpawnCount()` to `1..10`.

- `Count = 1` emits `SPAWN_ENEMY`.
- `Count > 1` emits `SPAWN_ENEMY_GROUP`.
- Changing count does not reset Type, selected FSM preset, formation, spacing, elasticity, or Y.
- Group-only rows are hidden at `Count = 1` and shown at `Count > 1`.

## Formation icon controls

Formation controls are icon-only buttons backed by current runtime formation IDs:

- `line.horizontal` → `━`
- `wedge` → `⌃`
- `column.vertical` → `┃`
- `arc.forward` → `◜`
- `ring` → `○`

The buttons update the existing formation choice state and carry `title`, `aria-label`, and `aria-pressed`.

## Spacing slider

Spacing is `#ds-fsm-spacing`, a native range input.

- min: `16`
- max: `96`
- step: `2`
- default: `18`

The slider writes `params.formation.spacing` in the existing group payload. U1.2.1 corrected the pre-merge native range step from `4` to `2` so the intended default `18` is aligned with the slider sequence and remains the initialized DOM value.

## Elasticity slider

Elasticity is `#ds-fsm-elasticity`, a native range input.

- min: `0`
- max: `10`
- step: `1`
- default: `0`

## Elasticity-to-runtime mapping

`mapElasticityToGroupSettings()` adapts the single UI slider to the existing group payload fields:

- `0` → `{ cohesionId: "rigid", response: 7, maxCatchupSpeed: 480 }`
- `1..10` → `cohesionId: "elastic"`
- elastic `response` moves monotonically from the existing response max toward min as elasticity increases.
- elastic `maxCatchupSpeed` moves monotonically from rigid default toward the existing catch-up min as elasticity increases, rounded to the existing step.

No SpawnSystem or group runtime contract was changed.

## Y slider

Y remains the existing native range input `#ds-screen-y`.

- min: `0`
- max: `logicH` (504 in current smokes)
- step: `1`
- default: `260`

The numeric value is still used as the spawn Y/anchor Y coordinate. Lower numbers are higher on screen in the current coordinate system.

## Spawn dispatch behavior

FSM mode has an FSM-only spawn branch:

- `Count = 1` calls `createDevSummonerSpawnPayload()` with `fsmPresetId` and without `behaviorPresetId`.
- `Count > 1` calls `createDevSummonerGroupSpawnPayload()` with `fsmPresetId`, selected formation, spacing, and mapped cohesion settings.

## Spawn contract preservation

`behaviorPresetId` remains reserved for Simple/Smart movement. FSM mode emits `fsmPresetId`. Group spawns still use the existing group movement preset and group movement ownership path.

## Existing FSM editor retained

`#ds-fsm-preset-editor`, authoring sections, Preview, Diagnostics, Runtime Trace, and `#ds-enemy-lab-debug` remain below BASIC SETUP.

## Risks and inputs for U1.3

- PRESETS icon import intentionally uses the existing lower import textarea/collision selector; a future file picker can wrap the same model API.
- Group-only controls are hidden by count in FSM mode, while Simple/Smart continue to use the previous shared Single/Group controls.
- Elasticity is a UI adapter over current `cohesionId`, `response`, and `maxCatchupSpeed`; future visual polish should keep the documented mapping or migrate it deliberately.
