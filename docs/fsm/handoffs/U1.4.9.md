# U1.4.9 — General group Follow delay

## Product semantics
Follow is a general group-motion delay measured in seconds per member. Member slot `0` uses the current group-anchor sample, slot `1` uses `1 × Follow` seconds of anchor history, and later members use progressively older samples.

## Follow versus Elasticity
Follow chooses which historical anchor path sample a member targets. Elasticity still only controls how strongly the member converges toward that target through the existing cohesion response/catch-up settings.

## Canonical data model
The canonical field is `followDelay` on `basicSetup` and on each FSM state. The visible UI label is `Follow`.

## Legacy normalization
Missing Basic Setup `followDelay` defaults to `0`. Missing state `followDelay` falls back to the normalized Basic Setup value. Loading legacy storage does not mutate saved JSON; saving writes canonical fields.

## Basic Setup UI
Basic Setup now orders group sliders as `Elasticity`, `Follow`, `Speed`. The slider uses runtime seconds directly with range `0..0.5`, step `0.01`, and default `0`.

## State UI
State formation controls now order sliders as `Spacing`, `Elasticity`, `Follow`, `Speed ×`. State Follow uses the same direct seconds range: `0..0.5`, step `0.01`, default `0`.

## Group history architecture
`EnemyGroupRegistry` owns a bounded per-group anchor history ring. Groups are initialized with the spawn anchor so early lookups clamp safely instead of reading invalid coordinates.

## Historical interpolation
Historical lookup computes `targetTime = now - slotIndex × followDelay`, clamps to the earliest/latest sample, and linearly interpolates between adjacent time-stamped anchor samples.

## Member ordering
Propagation order is deterministic slot order: member slot `0` is leader/least delayed and member slot `N` is most delayed. No alternate propagation modes were added.

## Delayed target calculation
Member target calculation is now `historical anchor position + current active formation offset`; the existing cohesion code then writes member velocity toward that target.

## Formation interaction
Historical formation replay was not added. State formation changes recompute current offsets and combine those offsets with historical anchor samples.

## Speed interaction
Follow is time-based, not distance-based. The same Follow requests the same sample age regardless of speed; faster anchor motion naturally creates a longer spatial trail along the path.

## State transition behavior
When the active state changes, its `followDelay` becomes effective immediately. Existing anchor history is preserved so transitions do not clear the trail buffer.

## Diagnostics
Runtime Diagnostics now reports compact group fields: active Follow, history sample count, and max trail delay.

## Persistence
Draft SPAWN carries unsaved Basic Setup and state `followDelay`. User Save persists Basic Setup and state `followDelay`. Built-in presets remain read-only/immutable.
