# U1.3.3 — Real scrollX for group-anchor FSM transitions

## Confirmed browser evidence

Post-A1.1 browser diagnostics showed that a single `fsm.charge` enemy at world X `17716` with world `scrollX` `17704` reported screen X `12` and transitioned from `enter` to `charge`. The same preset spawned as a group anchor reported anchor world X `20356`, `scrollX` `0`, screen X `20356`, state `enter`, and no last transition.

## Root cause

`EnemyGroupRegistry.updateAnchors()` hard-coded the group-anchor FSM transition context to `scrollX = 0`. Screen-space conditions such as `screenXBelow: 650` therefore evaluated the anchor's full scrolled world coordinate instead of `worldX - currentWorldScrollX`.

## Previous single-enemy context

`EnemySystem.update()` read the authoritative world scroll from `this.world.scrollX` and passed it into each single-enemy `updateResolvedFsm()` call. Single enemies therefore evaluated screen-space FSM transitions against the current simulation frame's world scroll.

## Previous group-anchor context

`EnemySystem.update()` called `enemyGroups.updateAnchors(...)` before deriving and passing any scroll value. `EnemyGroupRegistry.updateAnchors()` then set `group.fsmLastScrollX = 0` and forwarded that value to `updateResolvedFsm()` for the anchor runtime.

## Production fix

`EnemySystem.update()` now derives `scrollX` once at the start of the enemy update and passes it into `EnemyGroupRegistry.updateAnchors()`. The group registry records that value in `group.fsmLastScrollX` and passes it to the anchor `updateResolvedFsm()` call.

## scrollX source of truth

The source of truth remains the shared world state object (`world.scrollX`) already injected into `EnemySystem`. `EnemyGroupRegistry` does not calculate scroll independently.

## updateAnchors signature change

`EnemyGroupRegistry.updateAnchors(dt, ctx)` now requires `ctx.scrollX` in addition to `playerPos`, `logicW`, and `logicH`.

## Position integration ownership

Position ownership is unchanged. `EnemyGroupRegistry.updateAnchors()` still evaluates the group FSM or normal group behavior, writes `group.vel`, and integrates `group.anchor` exactly once at the end of each group update.

## Diagnostics change

Group diagnostics now report the real scroll context used by the anchor FSM after anchor updates. Screen X remains reported as `worldX - scrollX`.

## Single/group parity proof

`FsmGroupScreenXTransition.smoke.ts` creates scrolled-world conditions where `worldX = 20356`, `scrollX = 20100`, and screen X is `256`. It proves that single `fsm.charge` and group-anchor `fsm.charge` both transition from `enter` to `charge` with the same screen-X semantics, and that `fsm.hover` also leaves `enter` when its screen-X condition is satisfied. A negative control keeps screen X above the Charge threshold and verifies the group remains in `enter`.

## Affected presets

The fix applies to all group-anchor FSM presets whose transitions depend on screen-space X conditions, including the observed `fsm.charge`, user FSM turret, `fsm.smart-aligner`, smart-evader, and `fsm.zigzag` cases. Presets without the same screen-X transition dependency keep their existing behavior.
