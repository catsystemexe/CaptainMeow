# U1.4.13 — User preset rename and delete

## Product behavior

The FSM PRESETS toolbar now exposes compact management controls for selected user presets: rename with the edit/pencil glyph and delete with the trash glyph. The controls sit beside the existing preset toolbar controls above the current preset selector.

## Built-in immutability

Built-in presets remain read-only. Rename and delete controls are hidden for built-in selections, and the model/store reject built-in rename/delete calls.

## Rename UX

Clicking rename opens a compact browser prompt seeded with the current preset name. Confirming the prompt renames the selected user preset. Canceling the prompt makes no model or storage change.

## Rename validation

Rename trims whitespace and rejects empty or whitespace-only names. Duplicate display names remain allowed because preset identity stays ID-based.

## Delete confirmation

Delete uses a confirmation dialog that includes the selected preset name, for example `Delete preset "User FSM Turret"?`. The first click never deletes without confirmation.

## Selection fallback

After deleting the selected user preset, selection falls back deterministically to the next user preset in visible order, then the previous user preset, then the first built-in preset.

## Dirty-draft behavior

Deleting a selected user preset with unsaved authoring draft changes adds an explicit unsaved-changes warning to the confirmation. Rename persists the preset name immediately and does not save dirty graph/basic-setup draft content; the dirty draft remains dirty in memory.

## Store operations

`UserFsmPresetStore` now has narrow typed operations:

- `renameUserPreset(id, nextName)` updates only the target user preset's display name and preserves the preset ID.
- `deleteUserPreset(id)` removes only the target user preset.

The legacy `delete(id)` method delegates to `deleteUserPreset(id)` for compatibility.

## Persistence safety

Rename and delete commit through the existing store commit path and do not mutate localStorage directly from `DevSummoner`. Regression smoke coverage seeds 10 user presets, proves rename keeps 10, delete leaves 9, unrelated IDs remain, unrelated definitions remain deep-equal, and the raw storage envelope remains valid.
