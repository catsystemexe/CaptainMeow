## Old FSM LAB UI

Before U1.4, the Enemy Lab FSM authoring area exposed a dense all-at-once editor under `FSM Presets`: preset details, an explicit initial-state selector, a state selector plus raw state id/label inputs, separate always-visible Movement, Modifiers, Targeting, Combat, Lifecycle, Transitions, Diagnostics, Preview, and Save/Cancel sections. This made the main FSM LAB long and mixed core sequence authoring with advanced runtime details.

## New FSM LAB UI

U1.4 keeps the PRESETS toolbar and Save controls in the upper PRESETS/preset editor area, then places FSM authoring below BASIC SETUP in a simpler vertical flow:

1. `STATES` list first.
2. `SELECTED STATE` editor below the list.
3. Diagnostics and Preview remain below authoring.

The state list is narrow and vertical. Each row contains a drag-handle marker, a white square with a black order number, the behavior preset id as the main label, a small trigger summary, and a `⋯` row menu button. The selected row is highlighted.

The selected-state editor exposes only the main blocks:

- Behavior — movement/behavior preset select.
- Formation — per-state optional override toggle, icon-only shape buttons, spacing, elasticity, and speed-multiplier sliders.
- Trigger — simplified trigger type selector with only relevant params shown.
- Advanced — collapsed details for targeting/combat/modifiers/lifecycle.

## State numbering contract

State numbers are not saved ids and do not encode `enter`/`retreat`. They are derived in the UI model from `graph.states` order as `index + 1`. Reordering states changes the displayed numbering immediately.

## Trigger-to-next contract

The simplified FSM LAB treats trigger targets as sequential:

`state[i] -> state[i + 1]`

The editor does not expose a general target selector. `Never` clears outgoing transitions for the selected state. `Time`, `screenXBelow`, and `Hit` create/update a single transition to the next state. The last state has no next state and `Never` is valid.

`Hit` is represented in the existing runtime schema as an `hpBelow` condition with a default ratio. Runtime FSM condition semantics were not changed.

## Formation override contract

The selected-state editor owns a lightweight UI-model `formationOverride` object on draft state data. When disabled, the state inherits Basic Setup formation. When enabled, the draft stores shape, spacing, elasticity, and speed multiplier for UI/model authoring. Runtime formation movement semantics were not changed in this session.

## Advanced section scope

Advanced is intentionally minimal and collapsed by default. It reports existing selected-state targeting, combat, modifier, and lifecycle data without exposing the old always-open controls in the main path. No graph canvas or node editor was added.
