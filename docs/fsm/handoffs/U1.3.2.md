# U1.3.2 — Remove preset-default Count dependency

## Confirmed browser regression

After U1.3.1, the product rule was still at risk in the browser path: selected FSM preset identity must define behavior, while the visible/current Basic Setup Count must define single-versus-group cardinality. A default-single preset such as `fsm.charge` must not lose its selected graph when the unsaved draft Count changes to `2+`.

## Why Turret worked

`fsm.turret` was the first built-in preset and matched the authored `fsm_turret` enemy default graph path used by older spawn flows. That made it easy for a missing or stale explicit FSM selection to appear correct: the SpawnSystem could still resolve the enemy type's default `behaviorGraphId` and create a group anchor runtime for Turret-like cases.

## Why default-single presets failed

Default-single presets such as `fsm.charge` depend on the explicit selected `fsmPresetId` coming from the current Enemy Lab draft. If a group spawn path allowed normal group movement to remain authoritative, or if the explicit selected preset was dropped and the enemy type had no matching `behaviorGraphId`, the group anchor could fall back to normal movement instead of the selected FSM graph.

## Exact stale/incorrect condition

The incorrect dependency was allowing the FSM group spawn path to carry the generic group movement selector as the group movement behavior even when an FSM preset was selected. This let normal group movement remain a meaningful fallback beside the selected FSM. The corrected FSM path makes `none.hold` the non-authoritative movement fallback whenever the current FSM draft emits an explicit group `fsmPresetId`.

## Current draft versus persisted Count

The visible Count control updates `groupCount`, calls `FsmPresetEditorModel.setBasicSetup()`, and stores the unsaved value on `draft.basicSetup.count`. The Spawn button reads the current normalized `groupCount`; `Count = 1` emits `SPAWN_ENEMY`, and `Count > 1` emits `SPAWN_ENEMY_GROUP` with that current count.

Persisted or default preset Count remains separate. Built-in and legacy presets that lack `basicSetup` normalize to draft Count `1`, but changing the visible draft Count immediately changes spawn cardinality without saving the preset.

## FSM resolution path

The DevSummoner FSM dropdown owns the selected preset ID. FSM group spawn payloads carry that ID as `fsmPresetId`. SpawnSystem resolves explicit `fsmPresetId` through `CONTENT.fsmPresets`; invalid explicit IDs still throw before creating a group. When a resolved FSM preset exists, SpawnSystem passes it to `EnemyGroupRegistry.create()`, which creates one anchor FSM runtime.

## Production fix

FSM group spawns now submit `movementPresetId: "none.hold"` from DevSummoner while preserving the selected `fsmPresetId`. The group anchor FSM decision therefore depends on the resolved selected FSM preset plus the current group spawn request, not on authored/default Basic Setup Count.

## Group FSM invariant

For every valid selected FSM group spawn, `EnemyGroupRegistry` must store a non-null anchor FSM runtime whose preset identity matches the requested `fsmPresetId`. Normal group movement remains only a `none.hold` fallback and is not authoritative.

## Legacy preset behavior

Legacy user presets without stored `basicSetup` normalize to draft Count `1`; an unsaved draft Count override to `2` still creates a selected-FSM group anchor runtime. No save is required before spawning.

## Runtime test matrix

| Preset | Preset/default Count | Spawn Count | Expected |
|---|---:|---:|---|
| `fsm.turret` | normalized/default 1 or existing value | 2 | Turret FSM anchor |
| `fsm.charge` | 1 | 2 | Charge FSM anchor |
| `fsm.hover` | 1 | 3 | Hover FSM anchor |
| `fsm.charge` | 1 | 1 | Charge single enemy |
| `fsm.charge` | 1 | 2 then 1 then 3 | Charge remains selected |
| legacy/no `basicSetup` | normalized 1 | 2 | selected FSM anchor |

DevSummoner browser/group smokes now cover Charge as a default-single preset, Turret continuity, user preset continuity, selected payload identity, group runtime identity, and `none.hold` fallback suppression.
