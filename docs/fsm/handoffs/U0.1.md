# U0.1 — Group FSM spawn propagation fix

## Goal

Fix the Enemy Lab group-spawn contract so a selected explicit `fsmPresetId` is preserved through the browser group payload and applies to every spawned member while leaving group formation movement ownership unchanged.

## Confirmed browser bug

Manual browser verification after U0 reported that single spawn used the selected explicit FSM preset, but group spawn with a selected explicit FSM preset produced members that fell back to their appearance/default controller behavior.

## Root cause

The current code already forwards `SPAWN_ENEMY_GROUP.fsmPresetId` into each per-member `spawnEnemy` call. The remaining broken link was error visibility and coverage for the actual DevSummoner browser group path: group member spawn errors were caught inside the group loop, empty groups were removed, and the loop stopped without surfacing explicit FSM ID failures. This made the group path capable of silently falling back/stopping instead of failing clearly when the explicit selected group FSM could not be resolved.

## Why the original U0 smoke missed it

The U0 group smoke emitted `SPAWN_ENEMY_GROUP` directly against `SpawnSystem`. It verified a built-in explicit ID on one direct event path, but it did not exercise `createDevSummonerGroupSpawnPayload`, did not prove the browser helper kept FSM IDs out of `behaviorPresetId`, did not cover user FSM presets from `CONTENT.fsmPresets`, did not cover default `behaviorGraphId` override, and did not assert invalid explicit group ID behavior.

## Actual group spawn path

```text
DevSummoner Spawn Group button
→ createDevSummonerGroupSpawnPayload({ ..., fsmPresetId: fsmSpawnSelect.value || undefined })
→ bus.emitNext(EventType.SPAWN_ENEMY_GROUP, payload)
→ SpawnSystem.update SPAWN_ENEMY_GROUP case
→ per-member this.spawnEnemy({ typeId, spawn, behaviorPresetId: "none.hold", fsmPresetId, group })
→ spawnEnemy FSM precedence resolver
→ createFsmRuntimeSnapshot on each member
→ EnemyGroupRegistry membership is attached for formation movement ownership
```

## Patch

- Preserved the existing per-member forwarding of `fsmPresetId` from group payload to `spawnEnemy`.
- Changed the group member loop so errors from an explicit group `fsmPresetId` are rethrown after empty-group cleanup, preserving the clear `Unknown explicit fsmPresetId` failure from the shared single-enemy resolver.
- Expanded `FsmGroupSpawnOverride.smoke.ts` to cover built-in FSM group spawn, user FSM group spawn, default `behaviorGraphId` override, group membership, movement suppression ownership, no storage mutation during spawn, and invalid explicit ID cleanup/failure.
- Added `DevSummonerFsmGroupSpawn.smoke.ts` to exercise the same public helper/event/runtime path used by the browser group Spawn button.

## FSM precedence after fix

For each group member, `spawnEnemy` still owns FSM resolution with this precedence:

```text
resolvedFsmPresetOverride
→ fsmPresetId
→ enemyDefinition.behaviorGraphId
→ no FSM
```

Groups do not perform separate FSM resolution and no group-level FSM was added.

## Group ownership semantics preserved

Group members are still spawned with `behaviorPresetId: "none.hold"` and attached to `EnemyGroupRegistry`. The group controller remains the owner of anchor/formation movement; individual FSM movement remains suppressed by group membership while FSM transitions, combat selection, targeting, and lifecycle runtime remain active.

## Built-in FSM group behavior

`red` group spawn with explicit built-in `fsm.hover` produces three live members, each with runtime preset `fsm.hover`, live group membership, and `behaviorId === "none"` for formation ownership.

## User FSM group behavior

A user preset created through `FsmPresetEditorModel` is available through `CONTENT.fsmPresets`; group spawn with that user ID produces three live members whose FSM runtime preset ID matches the user preset. The smoke snapshots `inspectRawStorage().raw` before and after spawn and asserts it is unchanged.

## Invalid explicit ID behavior

Invalid explicit group `fsmPresetId` now propagates the shared SpawnSystem error, matching `/Unknown explicit fsmPresetId/`, and removes the empty group created before the first failed member spawn.
