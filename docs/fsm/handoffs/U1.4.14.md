# U1.4.14 — Preset toolbar audit and repair

## Confirmed browser symptom
The compact PRESETS toolbar was reported as showing seven controls (`+`, pencil, duplicate, up-arrow, reset, check, trash), with only New visibly working.

## Audit findings
The toolbar was constructed in `DevSummoner.ts` as seven fixed-position icon buttons. The buttons were not described as named actions, so the toolbar contained unrelated controls beside preset lifecycle controls.

## Existing icon-to-action mapping
| Visible icon | DOM/action | Tooltip/title | Intended/actual action | Works? | Observed defect |
|---|---|---|---|---|---|
| `+` | first toolbar button | New FSM preset | create user preset | Yes | Did not reload authoring model explicitly after creation. |
| `✎` | second toolbar button | Rename selected user FSM preset | rename selected user preset | User only | Hidden for built-ins; title did not match required accessible label. |
| `⧉` | third toolbar button | Copy selected FSM preset for editing | only duplicated built-ins before this fix | Partial/no-op for users | Handler only called `duplicateForEdit()` when the selected preset was built-in. |
| `⇧` | fourth toolbar button | Import FSM preset JSON from import box | import | No in compact PRESETS workflow | Extra import/up-arrow action; import textarea is not mounted in normal FSM layout. |
| `↻` | fifth toolbar button | Restart latest manual spawn with current FSM draft | spawn restart | No for preset reset | Extra/non-preset action, not Reset preset. |
| `✓` | sixth toolbar button | Save selected FSM preset | save | Partial | Visual check was wired, but event was unguarded and sizing differed by glyph. |
| `🗑` | seventh toolbar button | Delete selected user FSM preset | delete | User only | Hidden for built-ins; title did not match required accessible label. |

## Root cause per broken icon
- Edit name: model path existed, but the compact toolbar label/state contract was incomplete and the control was hidden for built-ins.
- Duplicate: handler only duplicated built-ins (`if builtin duplicateForEdit`), so selected user presets made it appear non-functional.
- Up-arrow: it was Import JSON, not a required preset action, and depended on legacy import controls that are not mounted in the normal toolbar flow.
- Reset/rotate: it restarted the latest manual spawn, not reset the selected preset draft.
- Save/check: save existed but lacked the explicit guarded toolbar action wiring and shared visual contract.
- Delete/trash: model path existed; user-only enablement remains, now with explicit button disabling and required label.

## Removed extra action
Removed the compact Import/up-arrow action and the compact Restart-spawn action from the PRESETS toolbar. Preset import/export was not changed elsewhere.

## Final six-action toolbar
The final compact toolbar is exactly: New, Edit name, Duplicate, Reset, Save, Delete.

## Event wiring repair
Each compact toolbar button is created with an explicit `data-preset-toolbar-action`, `type="button"`, title, and aria-label. Click handlers prevent default form behavior, stop propagation, check disabled state where needed, and reload/re-render the current model state after mutations.

## New behavior
New creates exactly one editable user preset, selects it, and reloads the authoring model for that preset.

## Edit-name behavior
Edit name uses `renameSelected`, preserves the selected user preset ID and FSM content, and refreshes model/list state. Built-ins are disabled.

## Duplicate behavior
Duplicate now calls `presetModel.duplicate()` for built-in and user presets, creates a new user preset ID, deep-clones content through the existing model/store path, selects the copy, and reloads authoring.

## Reset behavior
Reset uses the existing cancel/reload path (`authoringModel.cancel()` and `presetModel.cancel()`). It discards transient draft edits, reloads the last saved/canonical selected preset, clears dirty state, and preserves selection. It does not delete presets.

## Save behavior
Save persists user draft authoring changes and preset metadata/basic setup through the existing save path, then clears dirty state. Built-ins are disabled rather than copied on save.

## Delete behavior
Delete reuses the typed U1.4.13 delete path, asks for confirmation, deletes only the selected user preset, and lets the model choose a deterministic fallback.

## Built-in enablement rules
For built-in selections: New, Duplicate, and Reset remain available; Edit name, Save, and Delete are disabled. Reset reloads immutable built-in state and clears transient draft edits.

## Shared icon sizing
All six compact toolbar buttons use the shared `preset-toolbar-button` class/style: 26px outer box, zero padding, inline-flex centering, 14px/1 monospace icon font, and the same disabled treatment. Each glyph is wrapped in a shared `preset-toolbar-icon` 18px box.

## Accessibility labels
Exact labels are used: New preset, Edit preset name, Duplicate preset, Reset preset, Save preset, Delete preset.
