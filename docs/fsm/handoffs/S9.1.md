# S9.1 — Restore Enemy Lab visibility and mount path

## Observed issue

After S9, the Enemy Lab preset-management UI existed in `DevSummoner`, but users could not reliably see or reach the S9 `FSM Presets` panel in the visible Dev UI area.

## Proven root cause

`DevSummoner.init()` mounted the Enemy Lab panel directly into `document.body` and appended the S9 preset editor before the debug panel. The panel itself was present, but the fixed-width panel used `overflow:hidden` with no viewport-bounded vertical scrolling. With the expanded spawn controls above it, the lower preset-management section could be clipped off-screen and had no scroll path, making Enemy Lab preset management effectively invisible/unreachable.

S9 tests missed this because they covered the editor model, import/export behavior, and spawn payload/user-preset integration. They did not assert the actual panel mount/discoverability contract or the container style that determines whether the mounted S9 UI can be reached in the browser.

## Mount/visibility fix

S9.1 keeps the existing `DevSummoner` mount lifecycle and body mount path, but centralizes the panel IDs/style into exported mount-contract helpers and changes the panel container from permanent clipping to viewport-bounded vertical scrolling:

- `dev-summoner` remains the single mounted Enemy Lab root.
- `ds-fsm-preset-editor` remains the S9 preset-management panel.
- `ds-enemy-lab-debug` remains the runtime inspection panel.
- the root panel now has `max-height:calc(100vh - 16px)`, `overflow-x:hidden`, and `overflow-y:auto`.

This preserves all S9 preset-management behavior and existing spawn/gameplay controls while making the preset editor reachable.

## Regression coverage

Added `src/dev/EnemyLabVisibility.smoke.ts` to assert:

- the DevSummoner/Enemy Lab entry text exists,
- the panel mounts through the existing lifecycle,
- the mount occurs exactly once,
- the S9 preset editor has a discoverable container,
- `FSM Presets`, `BUILT-IN`, and `USER` labels remain present,
- the panel style is viewport-bounded and scrollable instead of permanently clipped,
- the duplicate-mount guard remains present,
- no S10 graph/state authoring controls were introduced.
