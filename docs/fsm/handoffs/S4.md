# S4 — State entry, runtime reset, combat modes, and timing semantics

## Session commit

The commit containing the S4 implementation.

## Goal

Implement the first intentional FSM runtime semantic upgrade after S3: formal state entry, spawn entry, deterministic runtime reset, explicit combat modes, combat reset/preserve policy, and revised state-age timing.

## Starting S3 semantics

- Spawn initialized `ent.fsm = createFsmRuntimeSnapshot(fsmPreset)` and then deleted `fsmAppliedMovementPresetId` in `SpawnSystem`.
- The S3 age flow evaluated transitions before incrementing age; transition ticks set age to `0` and returned without executing/incrementing the target state in the same tick.
- The S3 combat bridge used `getLegacyAttackProfileId(state)` for profile states and otherwise fell back to `def.attackProfile` in `EnemySystem`.
- The movement compatibility field was `fsmAppliedMovementPresetId`, used by the existing movement preset bridge to avoid repeated reapplication.

## Implemented scope

- Added a formal FSM state-entry helper and made spawn call it exactly once.
- Replaced S3 timing with S4 timing: evaluate transitions using tick-start age, enter a target immediately, execute the active state for the tick, then increment that state's age by `dt`.
- Added explicit runtime combat selection for `disabled`, `inherit`, and `profile` modes.
- Added explicit combat runtime reset/clear/preserve policy.
- Reset legacy movement application compatibility state on every formal entry.
- Added focused state-entry and combat-mode smoke tests.
- Updated S3 runtime parity smoke to preserve unaffected legacy behavior while asserting the intentional S4 age delta.

## Formal state-entry contract

- Spawn calls `createFsmRuntimeSnapshot(..., ent, { inheritedAttackProfileId })`, which creates a snapshot shell and calls `enterResolvedFsmState` for the initial state exactly once.
- Transitions call `enterResolvedFsmState` before state execution in the transition tick.
- Self-transitions are formal entries with `selfTransition === true`.
- Internal cleanup resets `fsmAppliedMovementPresetId` and resets or clears `bState.attack` unless same-profile preservation is explicitly allowed.
- User-facing `enterActions` remain data-only and are not executed.

## New age and transition semantics

- At tick start, `runtime.age` is the age already accumulated by the active state.
- Ordered transitions are evaluated using that age; `timeInState` uses `>=`.
- If a transition matches, the first match enters immediately and no second transition is evaluated that tick.
- The currently active state after any transition is the state observed by EnemySystem for movement/combat in that same tick.
- `runtime.age += dt` occurs exactly once after transition evaluation for the state that executed.
- Boundary example: with `timeInState >= 1.0` and `dt = 0.25`, the state reaches age `1.0` after four execution ticks, transitions at the start of the next tick, executes the target, and ends with target age `0.25`.
- Immediate transition behavior: a transition eligible at age `0` enters the target before source execution; the target ends with age `dt`, and chained target transitions wait until a later tick.

## Movement reset policy

- Formal entry deletes `entity.fsmAppliedMovementPresetId`.
- Transitioning between two states that use the same movement preset still forces reapplication through the legacy bridge.
- Self-transition also forces reapplication.
- No-transition ticks do not reset or reapply the preset.

## Combat mode semantics

- `disabled` resolves to `profileId = null` and no active attack profile.
- `inherit` resolves to the enemy-definition/default attack profile ID when present.
- `inherit` with no inherited profile resolves to `profileId = null` without an error.
- `profile` resolves to the state's concrete `profileId`.

## Combat runtime policy

- Reset on initial profile entry, different profile entry, same profile with default/reset policy, self-transition, disabled/inheritless to profile, inherit to profile, profile to inherit, and profile to disabled/inheritless.
- `preserveIfSameProfile` preserves only for non-self transitions into `mode: "profile"` with the same concrete profile ID.
- Preservation across different concrete profile IDs is forbidden.
- Cleared fields are the profile-scoped attack runtime stored at `entity.bState.attack`, currently including `cooldownMs`, `windupMs`, and `firing`.

## Semantic differences from S3

- Spawn is now a formal entry rather than only setting `stateIndex` and `age`.
- Transition ticks now execute the target state in the same tick and end with age `dt` instead of age `0`.
- Movement compatibility state resets on every formal entry, including same-preset transitions and self-transitions.
- FSM combat no longer implicitly falls back to the enemy definition for `disabled`; fallback happens only through explicit `inherit`.
- Attack runtime is reset/cleared/preserved by explicit entry policy instead of incidental `applyStateBehavior` preservation.

- `fsmAppliedMovementPresetId` remains the movement reapplication compatibility field.
- `updateResolvedFsmLegacySemantics` remains exported as a compatibility alias during the S4 transition.
- `enterActions` and migrated `despawn` remain resolved data only.

## Risks and required inputs for S5

- The remaining movement bridge is still `movementPreset`-based and should be the insertion point for S5 composition.
- The current reset seam is formal entry deleting `fsmAppliedMovementPresetId`.
- Modifier runtime slots are intentionally absent and must be designed without breaking group-controlled movement.
- Group-controlled movement interaction was not changed in S4 and must be audited before S5 movement composition changes.
