# U0 — Appearance/FSM spawn contract decoupling

## Goal

Decouple Enemy Lab appearance/type selection from FSM controller selection for normal spawns by adding an explicit persisted FSM spawn override field, `fsmPresetId?: string`.

## Starting bug

- Selecting an FSM preset and a non-FSM Type/appearance in Enemy Lab did not force that FSM controller.
- The normal spawn helper overloaded `behaviorPresetId` with FSM preset IDs.
- `SpawnSystem` ignored those IDs for FSM resolution and used only `enemyDefinition.behaviorGraphId`, so non-FSM appearances fell back to Simple/Smart movement/default behavior.

## Starting spawn paths

- Normal movement spawn: DevSummoner emitted `behaviorPresetId`; SpawnSystem materialized `EnemyBehaviorPresets` into `behaviorId`, `behavior`, and `bState`.
- Normal FSM spawn: default FSM controllers were derived only from `def.behaviorGraphId`.
- Draft preview: `FsmPreviewSession` passed `resolvedFsmPresetOverride` to `spawnPreviewEnemy`.
- Saved preview: `FsmPreviewSession` resolved selected saved presets from `CONTENT.fsmPresets` before spawning preview entities.
- Group spawn: group events spawned members with `behaviorPresetId: "none.hold"` and group membership for formation movement ownership.

## Implemented contract

- `behaviorPresetId` means Simple/Smart movement preset only.
- `fsmPresetId` means explicit normal persisted FSM controller preset ID.
- `resolvedFsmPresetOverride` remains the dev/test draft-preview-only resolved snapshot override.
- SpawnSystem precedence is:
  1. `resolvedFsmPresetOverride`
  2. `fsmPresetId`
  3. `enemyDefinition.behaviorGraphId`
  4. no FSM, preserving Simple/Smart movement.

## DevSummoner changes

Normal enemy spawn now sends movement selection as `behaviorPresetId` and FSM selection as `fsmPresetId`. Group spawn payloads also carry `fsmPresetId` while keeping group movement/cohesion fields separate. Normal spawn does not emit `resolvedFsmPresetOverride`.

## SpawnSystem changes

`SpawnSystem` forwards group `fsmPresetId` to each member and resolves FSM runtime once at spawn. Explicit `fsmPresetId` resolution uses `CONTENT.fsmPresets`, the combined built-in/user registry. Default `behaviorGraphId` fallback also uses the combined registry path. Unknown explicit IDs throw a clear `Unknown explicit fsmPresetId` error instead of falling back silently.

## Combined registry behavior

Built-in and saved user FSM IDs are both resolved from `CONTENT.fsmPresets`. Spawn does not read localStorage; storage remains isolated to `UserFsmPresetStore` construction and editing APIs.

## Appearance/controller independence

Smoke coverage proves:

- `red` + `fsm.turret` uses red appearance with turret FSM.
- `red` + `fsm.hover` uses red appearance with hover FSM.
- `blue` + `fsm.turret` uses blue appearance with turret FSM.
- `fsm_turret` + explicit `fsm.hover` overrides the default `fsm.turret` graph.

## Group compatibility

Group payloads carry `fsmPresetId`; SpawnSystem forwards it to every member. Members keep group membership and `none.hold` movement materialization so formation/cohesion movement ownership remains unchanged while FSM runtime is active.

## Invalid explicit ID behavior

An explicit missing `fsmPresetId` throws a clear SpawnSystem error and does not silently fall back to the enemy definition default graph. Missing default graph IDs continue to mean no FSM.

## Preview isolation

Draft preview still uses `resolvedFsmPresetOverride` and remains highest priority. The preview override remains a resolved runtime snapshot passed only through `spawnPreviewEnemy`; it is not inserted into registries or storage.
