# U1.4.16 — Preset dialog and label synchronization

## Confirmed browser symptoms
- Delete succeeded, but the dialog could show a generic or stale selected-preset label instead of the concrete current user preset name.
- Rename persisted to the model/store, but visible selected-preset and open-list labels could remain stale until another interaction forced a refresh.

## Audit findings
- `FsmPresetEditorModel.renameSelected()` already updates storage, preserves the selected ID, and reloads `draft` from the registry.
- The mounted FSM preset selector rendered IDs instead of canonical preset names, so it did not visibly reflect label changes.
- The compact selector rebuilt and closed its popover on every option refresh, preventing an already-open preset list from visibly updating in place.
- The authoring draft may hold a cloned preset while dirty, so its metadata label needed a non-saving in-memory sync after a store rename.

## Delete-name root cause
The delete click handler built its message from the handler's current draft snapshot. The safe source is the current selected preset item in `presetModel.list()` at click time, falling back to the draft only if needed.

## Rename-label root cause
The store/model label changed correctly, but visible labels were sourced from preset IDs and the compact list was closed during option refresh. Dirty authoring drafts also kept a cloned metadata name.

## Canonical label source
The canonical rendered label is the selected item label returned by `FsmPresetEditorModel.list()`, which is derived from the content/user preset registry metadata name.

## Delete dialog binding
The Trash2 click handler reads the current selected item label at click time and writes `Delete preset "NAME"?` through `textContent`.

## Current-label synchronization
After a successful rename, `presetModel.renameSelected(nextName)` reloads the editor draft, the dirty authoring draft metadata name is synchronized in memory when it is the same selected preset, and `renderPresetEditor()` refreshes the visible selected label immediately.

## Preset-list synchronization
The compact selector now preserves its open state while `setOptions()` rerenders rows. Preset options render `USER/BUILT-IN` plus the canonical preset label, so open-list rows update without a close/reopen interaction.

## Focus behavior
The rename dialog still uses the Pencil button as its opener. The toolbar buttons are stable DOM nodes, so closing the dialog returns focus to the current Pencil button after the label refresh.
