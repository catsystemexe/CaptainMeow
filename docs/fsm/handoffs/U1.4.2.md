# U1.4.2 — FSM LAB state interactivity

## Confirmed browser issues

- FSM LAB state rows were visible and bound to the selected preset, but their visible state-row controls were not reliable browser interactions.
- Move Up / Move Down did not stop row-level interaction and did not explicitly preserve accordion identity.
- State fields were rendered in an inline editor, but formation override disable semantics only stored `enabled: false` instead of returning to Basic Setup inheritance by removing the override.
- Expansion used selected-state identity only, so a selected expanded row could not be clicked again to collapse cleanly.
- The drag-handle glyph looked like an active drag affordance even though drag-and-drop was not implemented in this focused fix.

## Root causes

- The UI had no explicit accordion state separate from `selectedStateId`.
- Interactive row controls did not consistently stop event propagation from row-level click handling.
- Formation override state had no dedicated enable/disable model method, so disabling left stale state-level override data in the draft.
- Formation field editing relied on whole-object writes rather than targeted model methods that normalize field values.
- The decorative drag handle used an active-looking handle glyph without drag event wiring.

## Reorder event wiring

- Each row now renders boundary-disabled Move Up / Move Down buttons.
- Arrow clicks call `stopPropagation()`, select the row state, preserve `expandedStateId`, call `reorderState()`, call `normalizeSequentialTriggers()`, and rerender.
- First-state Move Up and last-state Move Down remain disabled/no-op and are styled as unavailable.

## Draft mutation and dirty tracking

- `reorderState()` remains the graph-order mutation point and marks the draft dirty only for real order changes.
- Movement/behavior, formation override, formation fields, and trigger edits all route through `FsmPresetAuthoringModel` mutation methods, which mark the authoring draft dirty.
- Boundary reorder no-ops do not dirty the draft.

## Behavior binding

- The Behavior select continues to write `state.movement.base.params.presetId` through `setMovementPreset()` for the selected state.
- The row label reads from `labStateRows()`, so rerender reflects the updated behavior preset id.

## Formation override toggle

- Added `setLabFormationOverrideEnabled(stateId, enabled)`.
- Enabling creates state override data from the current effective values, falling back to Basic Setup where needed.
- Disabling deletes the state-level `formationOverride`, returning the selected state to Basic Setup effective values.

## Formation field bindings

- Added `setLabFormationField()` for `shape`, `spacing`, `elasticity`, and `speedMultiplier`.
- Shape writes `formationOverride.shape`.
- Spacing, elasticity, and speed multiplier are normalized to finite values within the existing UI ranges before being stored.
- Formation controls are only shown/enabled when the override checkbox is on.

## Trigger bindings

- Trigger type and trigger parameter edits continue through `setLabTrigger()`.
- `Never` clears outgoing sequential transitions.
- `Time` writes `timeInState.seconds`.
- `screenXBelow` writes `screenXBelow.x`.
- `Hit` remains represented as `hpBelow` with the existing default ratio.
- Transition targets remain the next state in the current graph order.

## Expand/collapse model

- `DevSummoner` now owns an explicit `expandedStateId: string | null` accordion state.
- Clicking a collapsed row selects and expands it.
- Clicking the same expanded row selects and collapses it.
- Clicking a different row selects and expands only that row.
- The inline editor is appended only when `row.id === expandedStateId`, so zero or one editor is visible.

## Event propagation handling

- Inline editor `click`, `input`, and `change` events stop propagation to prevent controls from collapsing the row.
- Move arrows and duplicate controls stop propagation before mutating model state.
- The drag handle is now decorative with a default cursor and title directing users to the arrows.

## Manual browser verification

Not performed in this non-interactive session. The required manual checklist remains:

1. Open FSM mode.
2. Select a preset with at least 3 states.
3. Click state 2 and confirm editor opens below state 2.
4. Click state 2 again and confirm editor collapses.
5. Click state 3 and confirm only state 3 editor is open.
6. Click Move Up on state 3 and confirm state moves, numbers update, and editor remains on the same state.
7. Click Move Down and confirm reverse.
8. Change Behavior and confirm row label updates and preset is dirty.
9. Enable Formation Override and confirm controls appear.
10. Change shape, spacing, elasticity, and speed multiplier.
11. Collapse and reopen; confirm values persist.
12. Disable Formation Override and confirm the state returns to Basic Setup.
13. Change Trigger type and value.
14. Collapse and reopen; confirm trigger values persist.
15. Save preset, reload preset, and confirm reorder and edited values persist.
