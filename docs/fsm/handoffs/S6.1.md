# S6.1 — Dev UI runtime state compatibility

## Session commit

The commit containing this S6.1 compatibility fix.

## Goal

Restore Dev UI observability after the FSM runtime switched from the legacy graph/current-state shape to resolved runtime snapshots.

## Root cause

DevSummoner's Enemy Lab still derived the active FSM state from legacy content data and `entity.fsm.current`. Resolved FSM runtime now stores the active state as `entity.fsm.stateIndex` plus the resolved preset snapshot at `entity.fsm.preset.states`, so the panel could not highlight or display live state changes.

## Implemented scope

- Added a small read-only FSM debug snapshot helper.
- Updated DevSummoner/Enemy Lab runtime display to read resolved runtime snapshots.
- Preserved the existing 250 ms Enemy Lab refresh cycle and selected-entity lookup.
- Added focused smoke coverage for helper behavior and DevSummoner adapter usage.

## New read-only helper

- `getFsmDebugSnapshot(entity)` returns `null` for non-FSM entities.
- It reads only the entity-local resolved runtime snapshot.
- It does not perform registry lookup.
- It does not mutate runtime state.
- It exposes preset ID, state ID/label/index/age, entry count, combat mode/profile, movement preset, modifier types, and movement suppression.

## Updated components

- DevSummoner Enemy Lab now uses `getFsmDebugSnapshot` instead of `fsm.current` and legacy `BEHAVIOR_GRAPHS` lookup.
- The graph view is rendered from `entity.fsm.preset.states`, with the active row selected by `stateIndex`.
- The existing interval-based `refreshEnemyLab()` path still re-reads the current live entity from the store, so no new polling mechanism was added.

## Runtime behavior confirmation

FSM runtime behavior was not changed. This session did not alter transition timing, movement, combat, lifecycle, content, persistence, or spawn behavior.
