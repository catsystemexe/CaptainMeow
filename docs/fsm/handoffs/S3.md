# S3 — Runtime snapshot and graph resolution

## Session commit

The commit containing the S3 implementation.

## Goal

Refactor FSM enemy execution so spawned entities capture an immutable resolved built-in preset snapshot once, then execute each tick from entity-local mutable state indexes and age while preserving legacy observable behavior.

## Starting runtime path

- EnemySystem read `ENEMY_DEFS[e.typeId].behaviorGraphId` each tick.
- EnemySystem performed `BEHAVIOR_GRAPHS[graphId]` each tick.
- `updateFsm` called `ensureFsm(ent, graph)` each tick and rewrote `ent.fsm = { current, age }`.
- Current state was looked up by raw state string through `graph.states[fsm.current]`.
- Transition target was assigned from raw `transition.goto`, then target state was looked up by raw string.
- Legacy timing evaluated transitions before age increment, reset age to `0` on transition, did not increment age on a transition tick, used ordered first-match transitions, and returned immediately after one transition.

## Implemented scope

- Added a resolved FSM runtime module for S3 legacy-semantics execution.
- SpawnSystem now resolves a built-in FSM preset once for enemies with `behaviorGraphId` and stores the resolved preset reference in `ent.fsm`.
- EnemySystem now uses `ent.fsm.preset`, `stateIndex`, and `age` instead of raw graph lookup.
- Movement and combat continue through compatibility helpers that expose legacy movement preset ID and attack profile ID from the resolved state.
- Added focused runtime parity and determinism smoke tests.
- Updated the S2 content smoke assertion to reflect that EnemySystem no longer uses the legacy graph path.

## Spawn snapshot semantics

- Lookup point: `SpawnSystem.spawnEnemy`, immediately after the enemy behavior preset and base behavior runtime are initialized from the enemy definition.
- Stored reference: the exact `ResolvedFsmPreset` returned by `BUILTIN_FSM_PRESETS.get(def.behaviorGraphId)`.
- Initial state initialization: `stateIndex` is initialized to `preset.initialStateIndex` and `age` to `0`.
- Entity-local mutable fields: only `stateIndex` and `age` mutate during S3 runtime execution.
- If an enemy has no graph or no resolved preset, the entity has no `ent.fsm` snapshot and the non-FSM path remains unchanged.

## Preserved legacy semantics

- Transition evaluation order: ordered transitions are checked before age increment.
- Age timing: age is compared before increment; non-transition ticks add `dt`; transition ticks reset age to `0` and do not add `dt` afterward.
- First-match behavior: the first passing transition is selected and the evaluator returns immediately.
- Movement application/reset: EnemySystem still routes the resolved state's legacy movement preset ID through the existing `applyStateBehavior` path and keeps `fsmAppliedMovementPresetId` compatibility behavior.
- Combat fallback/persistence: resolved `combat.mode === "profile"` supplies the state attack profile; otherwise EnemySystem falls back to the enemy definition attack profile. Attack runtime is not reset on FSM state changes beyond existing `applyStateBehavior` preservation of `bState.attack`.
- Lifecycle not executed: `enterActions`, including migrated `despawn`, remain data-only.

## Removed hot-path work

- Removed EnemySystem per-tick `BEHAVIOR_GRAPHS[graphId]` lookup.
- Removed per-tick raw transition target string to state lookup from the active FSM branch.
- Removed per-tick `ensureFsm` wrapper/state allocation from the active FSM branch once a spawned snapshot exists.
- Removed per-tick built-in registry lookup from EnemySystem; registry lookup occurs at spawn-time snapshot creation.

## Parity baseline

- `FsmRuntimeParity.smoke.ts` keeps a test-only S3 parity oracle using the pre-S3 `updateFsm` legacy evaluator against controlled in-memory graphs.
- Scenarios covered:
  - time transition,
  - position/screen transition,
  - attack state,
  - first-match priority and one-transition-per-tick,
  - legacy `despawn` as data-only state,
  - movement preset bridge,
  - canonical JSON not modified.
- Compared fields include tick, state label, age, position, velocity, switched flag, attack observability, and movement preset ID.
- Result: resolved execution matched the legacy baseline in the focused smoke test.

## Determinism and multi-entity result

- `FsmDeterminism.smoke.ts` verifies identical resolved runs produce equal traces.
- Five entities share one immutable preset reference while retaining independent mutable `stateIndex` and `age`.
- Mutating one entity runtime does not mutate another.
- Registry replacement after spawn does not alter an entity's stored snapshot reference.
- Repeated runtime execution does not mutate the resolved preset.
- Source inspection assertions verify no per-tick graph lookup, no per-tick registry lookup, no repeated runtime initialization in EnemySystem, and no introduced `Math.random` in EnemySystem.

## Compatibility code deferred to S4/S5

- `getLegacyMovementPresetId` bridges resolved movement base data back to existing movement presets.
- `getLegacyAttackProfileId` bridges resolved combat profile data back to existing attack profile lookup.
- `fsmAppliedMovementPresetId` remains required for existing movement reset/re-entry behavior.
- The legacy `updateFsm` module remains exported for compatibility and test-only parity baseline use.

## Explicitly deferred

- new age semantics
- combat modes
- movement composition
- lifecycle execution
- canonical content conversion
- persistence/UI

## Risks and required inputs for S4

- S4 must intentionally decide when initial state becomes a formal entry and update parity baselines accordingly.
- Compatibility fields still present: `fsmAppliedMovementPresetId`, resolved-to-legacy movement preset extraction, resolved-to-legacy attack profile extraction, and legacy `updateFsm` for parity tests.
- S4/S5 may intentionally change movement reset semantics; S3 preserved current reset behavior.
- S4/S6 must decide when and how `enterActions` and explicit `despawn` are executed through the standard lifecycle.
- Any future combat-mode runtime implementation must explicitly replace the S3 fallback/persistence bridge and update attack cooldown parity tests.
