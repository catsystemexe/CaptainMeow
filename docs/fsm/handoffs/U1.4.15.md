# U1.4.15 — Lucide preset toolbar and in-app dialogs

## Confirmed browser symptom
Duplicate, Reset, and toolbar enablement were already functional after U1.4.14. Edit name and Delete still depended on native browser dialogs and were unreliable in iframe/Replit browser contexts.

## Audit findings
The toolbar button order was already correct: New, Edit name, Duplicate, Reset, Save, Delete. The Edit and Delete listeners were attached and guarded by the same built-in/user disabled state as the other actions. Direct model calls to `renameSelected()` and `delete(..., true)` worked in smoke coverage.

## Edit failure root cause
The first divergent point was the native `window.prompt("Rename FSM user preset", draft.label)` dependency in the Pencil click handler. When that dialog does not open or cannot return a value in the host browser context, the handler exits before `renameSelected()` and rerender.

## Delete failure root cause
The first divergent point was the native `window.confirm(...)` dependency in the Trash click handler. When that dialog does not open or cannot return `true` in the host browser context, the handler exits before `deleteSelected`/`delete(..., true)`, fallback selection, authoring reload, and rerender.

## Lucide dependency
Added `lucide` version `1.23.0`. `lucide-react` was not added because Enemy Lab is imperative DOM TypeScript rather than React.

## Icon mapping
- New: `Plus`
- Edit name: `Pencil`
- Duplicate: `Copy`
- Reset: `RotateCcw`
- Save: `Save`
- Delete: `Trash2`
- Delete dirty warning: `TriangleAlert`

`X` and `Check` remain available through the Lucide dependency if later dialogs need explicit close/check iconography, but U1.4.15 kept dialog actions as text buttons.

## Shared icon helper
Added `src/dev/ui/lucideIcon.ts` with `createLucideIcon({ icon, name, size = 18, strokeWidth = 2, className = "preset-toolbar-icon" })`. It creates SVG elements, applies the 24x24 Lucide viewBox, round caps/joins, `fill="none"`, `stroke="currentColor"`, `aria-hidden`, `focusable="false"`, `data-icon-name`, shared class, and `pointer-events: none`.

## Shared icon button
Added `src/dev/ui/iconButton.ts` with `createDevIconButton({ action, label, icon, iconName, onClick, disabled })`, `styleDevIconButton()`, and `setDevIconButtonDisabled()`. Buttons are `type="button"`, carry `data-preset-toolbar-action`, `aria-label`, `title`, the shared button class, and a Lucide SVG wrapper.

## Rename dialog
The Pencil action opens an in-app `openDevDialog()` dialog titled `Edit preset name`, prefilled with the current preset label. Confirm calls the existing `presetModel.renameSelected(nextName)` path and rerenders. The selected preset ID and graph/basic setup are preserved.

## Rename validation
Rename trims whitespace, rejects empty names with inline validation, treats the same name as a no-op, and does not save dirty FSM content while renaming metadata.

## Delete dialog
The Trash2 action opens an in-app `Delete preset` confirmation that displays the selected preset name. Confirm calls the existing delete API with confirmation, reloads the authoring model from the deterministic fallback selection, and rerenders.

## Dirty warning
If the selected authoring draft is dirty, the delete dialog shows a `TriangleAlert` warning that the preset has unsaved draft changes.

## Focus and keyboard behavior
The reusable dialog enforces a single active overlay, moves focus into the dialog, closes on Escape, treats Enter in an input as confirm, cancels on backdrop click, cleans listeners on close, and returns focus to the invoking toolbar button.

## Built-in enablement
Built-in selections keep New, Duplicate, and Reset available while Edit name, Save, and Delete are disabled through the existing render-time read-only checks.

## User enablement
User selections enable Edit name, Duplicate, Reset, and Delete. Save remains governed by the existing dirty/can-save product rule.
