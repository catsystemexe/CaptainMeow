# U1.4.1 — FSM LAB preset binding and inline state editors

## Confirmed browser issues

- FSM LAB state rows could remain bound to a stale authoring draft after the top preset selector changed.
- Reorder controls did not provide boundary-safe visible move-up / move-down behavior tied to the current draft graph.
- The selected-state editor was rendered as a detached section after the state list instead of inline below the selected state row.
- The normal FSM mode layout still mounted the legacy `FSM Presets` management panel and the `Runtime Diagnostics` panel between Basic Setup and FSM LAB.

## Root causes

- `DevSummoner` recreated or reloaded authoring state after other preset-editor fields had already been refreshed, and the FSM LAB state list relied on whatever `FsmPresetAuthoringModel` draft was currently present.
- `FsmPresetAuthoringModel.load()` always selected the graph initial state and did not explicitly reconcile an existing selected-state identity against the newly selected graph.
- The selected-state editor was created as a sibling authoring section after `STATES`, so rerendering the state rows could not place it under the selected row.
- The legacy preset-management DOM and runtime-diagnostics DOM were both mounted in the normal FSM section even though their model/debug infrastructure should remain available behind code paths and tests.

## Preset-to-state source of truth

FSM LAB rows now come from `FsmPresetAuthoringModel.draft.preset.graph.states` for the selected preset draft. The top PRESETS selector, selected-state editor, Preview Draft, and Save path all reference the same selected preset/draft model.

## Selection synchronization

`FsmPresetAuthoringModel.load()` accepts the previous selected-state id as a preferred identity. When the next graph contains that id, selection is preserved. Otherwise, selection falls back to the new graph's first state, or `null` for an empty graph.

## State reorder implementation

State reorder mutates the current draft graph order through `FsmPresetAuthoringModel.reorderState()`. The method clamps targets, treats same-index movement as a no-op, keeps the selected state id unchanged, updates the graph initial state to the new first state, and marks the draft dirty only when the order actually changes.

## Numbering behavior

State numbers remain UI-derived from `labStateRows()` as `index + 1`. No state number is stored in FSM graph data. After reorder, the rows rerender and numbers recompute from the new graph order.

## Trigger-to-next behavior after reorder

After UI move-up / move-down actions, `normalizeSequentialTriggers()` is called so existing sequential trigger conditions retarget the new next state. Terminal states keep no next-state transition.

## Inline editor rendering

The selected-state editor is now a single DOM node appended into `ds-fsm-state-list` immediately after the selected row during each render. Selecting a different state rerenders the list and moves that same editor node below the newly selected row.

## Legacy FSM Presets panel

The legacy full `FSM Presets` management panel is no longer mounted in the normal FSM menu layout. Its underlying editor model and detached controls remain in code for existing save/import/export/debug paths.

## Runtime Diagnostics panel

The runtime diagnostics section is no longer appended to the normal FSM menu layout. Runtime diagnostics extraction, rendering helpers, and smoke coverage remain present.
