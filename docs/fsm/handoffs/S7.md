# S7 — Canonical built-in FSM content conversion

## Goal

Convert built-in FSM content from legacy `behaviorGraphs.json` shape to canonical schema v1 content and remove production built-in dependence on the legacy migration adapter.

## Starting content path

- Starting production source: `src/game/content/behaviorGraphs.json` legacy graph object.
- Starting loader path: `behaviorGraphs.json → migrateBuiltinFsmPresets → validate/resolve → CONTENT.builtinFsmPresets`.

## Implemented scope

- Added canonical schema-v1 built-in source at `src/game/content/fsmPresets.json`.
- Converted all 10 built-in presets with explicit schema version, metadata, state IDs, labels, movement base, targeting, combat, lifecycle and ordered transitions.
- Updated content loading to build the built-in registry directly from canonical presets.
- Removed `CONTENT.behaviorGraphs` and deleted the production legacy graph JSON source.
- Kept legacy migration APIs for compatibility and tests.
- Added canonical content and runtime parity smoke coverage.

## Terminal/despawn decisions

All 10 legacy terminal states named `despawn` were converted to explicit schema-v1 lifecycle actions:

```json
"lifecycle": { "enterActions": [{ "type": "despawn" }] }
```

Reasoning:
- S6 made migrated terminal `despawn` active through explicit lifecycle data.
- S7 preserves the current S6.1 runtime behavior by encoding that action directly in canonical content.
- Runtime no longer relies on the state label; tests verify a state named `despawn` without action does not kill, while an explicit action on any label does kill.

## Loader and registry changes

- `loadContent()` imports `fsmPresets.json` instead of `behaviorGraphs.json`.
- Built-in registry construction now uses `buildBuiltinFsmPresetRegistryFromPresets()`.
- Enemy type `behaviorGraphId` cross-reference validation checks the resolved canonical registry IDs.
- `CONTENT` continues exposing `CONTENT.builtinFsmPresets` and `BUILTIN_FSM_PRESETS`.
- `CONTENT.behaviorGraphs` was removed.

## Legacy adapter policy

Retained compatibility APIs:
- `migrateLegacyBehaviorGraph()`
- `migrateBuiltinFsmPresets()`
- `buildBuiltinFsmPresetRegistry()` for legacy-shaped inputs

Removed production callers:
- `loadContent()` no longer imports legacy graph JSON.
- `loadContent()` no longer calls `migrateBuiltinFsmPresets()`.
- `CONTENT` no longer exports `BEHAVIOR_GRAPHS`.

Future deletion condition:
- Remove built-in migration helpers only after external/import compatibility requirements are finalized.

## Parity results

- Canonical preset IDs match the 10 legacy IDs in order.
- State IDs and labels match the deterministic S2 migration output.
- Movement preset IDs, targeting, combat modes, transition order and transition targets are preserved.
- S6 explicit despawn behavior is preserved as canonical data.
- Runtime snapshot/debug consumers continue reading resolved presets.
