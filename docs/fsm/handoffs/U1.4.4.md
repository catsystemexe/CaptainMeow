# U1.4.4 — Compact FSM LAB layout, diagnostics, Count, and Speed runtime fixes

## Motivation

U1.4.4 keeps the U1.4 sequential FSM LAB workflow but tightens the visible layout, restores the existing runtime diagnostics panel, and fixes two runtime regressions found in manual Enemy Lab FSM spawning: draft `Count > 1` group creation and Basic Setup `Speed` runtime application.

## Count regression root cause

The audited path was:

`draft Basic Setup Count → SPAWN → single/group branch → resolvedFsmPresetOverride → event → SpawnSystem → group → group anchor FSM → members`.

The current FSM SPAWN branch already uses `normalizeFsmSpawnCount(groupCount)`, emits `SPAWN_ENEMY` for `Count = 1`, emits `SPAWN_ENEMY_GROUP` for `Count > 1`, and forwards the current draft `resolvedFsmPresetOverride` through the event payload. The risk was insufficient regression coverage: prior checks focused mostly on payload shape and did not prove the actual group registry and created members matched the current draft Count.

## Count fix and runtime proof

U1.4.4 adds runtime smoke coverage that runs the spawn event through `SpawnSystem` and verifies actual group membership:

- `Count = 1` creates a single FSM enemy through `SPAWN_ENEMY`.
- `Count = 2` creates a group with two actual members.
- `Count = 7` creates a group with seven actual members.
- The group anchor uses the current draft FSM override.
- Manual-spawn correlation reaches all group members.

The Stop Latest Manual Spawn path remains token-based, so it stops only entities whose `devManualSpawnId` matches the latest manual spawn and removes only those groups.

## Speed root cause

Basic Setup `baseSpeed` was persisted on FSM presets but not applied to FSM movement runtime. Movement presets already contain absolute behavior parameters, so U1.4.4 avoids mutating preset parameters or multiplying those absolute values directly. Instead, it preserves the movement preset target direction/pattern and normalizes the resulting target-vector velocity to the desired effective speed.

## Runtime model

The runtime model is:

```text
effectiveSpeed = basicSetup.baseSpeed × state.speedMultiplier
```

Where:

- `basicSetup.baseSpeed` is read from the resolved FSM preset definition.
- `state.speedMultiplier` is read from the state `formationOverride` when enabled.
- The default multiplier is `1`.
- Legacy presets without `basicSetup.baseSpeed` keep prior absolute movement-preset behavior.

## Single/group proof

The new runtime smoke verifies:

- `baseSpeed 100 × 1.0` produces velocity magnitude approximately `100` for a single FSM enemy.
- `baseSpeed 200 × 1.0` produces velocity magnitude approximately `200` for a single FSM enemy.
- `baseSpeed 100 × 0.5` produces velocity magnitude approximately `50` for a single FSM enemy.
- The same multiplier model applies to group-anchor FSM velocity.
- Direction remains leftward for the covered straight movement path.
- Group members remain formation-controlled by the anchor.

## Legacy compatibility

Legacy presets without Basic Setup speed continue to use existing movement-preset absolute speeds. Simple and Smart runtime paths are unchanged because the speed normalization is applied only inside FSM movement integration.

## UI changes

- FSM LAB width is now responsive and approximately 20% wider.
- Small icon buttons no longer render a fixed visible border by default; hover/focus/disabled semantics remain native button semantics with title and aria labels preserved.
- The non-functional drag handle before state numbers was removed.
- `Override formation for this state` is shortened to `Override`.
- Trigger steppers render on one row as `Time/scrX/Hit [−] [value] [+]`.
- `screenXBelow` remains the runtime ID while the UI label is `scrX`.
- Time uses whole seconds, step `1`, minimum `0`.
- `scrX` uses step `10`.
- Hit uses step `1`, minimum `1`.

## Diagnostics restoration

The existing Runtime Diagnostics panel is mounted once in the FSM LAB flow after authoring. No new diagnostics system or duplicate timer was added. The restored panel continues to use `findLatestFsmRuntimeDiagnostics` and `renderFsmRuntimeDiagnosticsText`, preserving manual-spawn correlation, real `scrollX`, and single/group-anchor/member diagnostics.

Visible order is now:

1. PRESETS
2. BASIC SETUP
3. FSM LAB authoring
4. RUNTIME DIAGNOSTICS
